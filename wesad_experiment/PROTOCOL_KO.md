# WESAD 기반 설명 가능한 휴식 알림 실험

작성일: 2026-11-01. 이 문서는 분석 전 고정한 수업용 탐색 실험 설계이며 임상 검증이나 사전등록 완료를 뜻하지 않는다.

## 연구 질문과 앱

앱 콘셉트는 웨어러블로 최근 60초의 스트레스 실험 조건을 추정하고, 근거를 보여준 다음 사용자가 휴식 알림 수신 여부를 선택하는 도구다. 앱이 생산성을 높이는지, 쉬면 스트레스가 감소하는지는 이 데이터만으로 검증하지 않는다.

RQ1: 처음 보는 참가자의 손목 센서 데이터에서 전통적 ML이 스트레스 실험 조건과 비스트레스 조건을 구분하는가?

RQ2: 같은 모델의 예측에 대한 SHAP, LIME, Anchors 설명이 설명 없는 화면에 비해 사용자의 모델 이해도와 오류 판별을 개선하는가?

H1은 설명 제공 시 이해도 상승이다. H2는 설명 제공 시 오답 예측의 무조건적 수용 감소다. 세 설명 방식 사이의 우열은 탐색적으로 분석한다. 사용자 신뢰가 높아지는 것 자체를 성공으로 정의하지 않는다.

## 1단계: 오프라인 모델 실험

| 항목 | 고정한 설계 |
|---|---|
| 참가자 | S2–S11, S13–S17, 총 15명 |
| 입력 | 손목 EDA 4Hz, BVP 64Hz, TEMP 4Hz, ACC 32Hz |
| 라벨 | 원본 label 2 → 스트레스 1; label 1·3 → 비스트레스 0; 나머지 제외 |
| 라벨 의미 | 실험 프로토콜 조건. 매 순간의 주관적 스트레스나 질병 진단이 아님 |
| 구간 | 같은 라벨의 연속 구간 양끝 5초 제외 후 60초, 비중첩 |
| 전처리 | 각 구간 안에서 EDA 1Hz 저역통과, BVP 0.7–3.5Hz 대역통과; ACC 원시 단위를 g로 변환 |
| 특징 | EDA·체온 평균/표준편차/범위/기울기, EDA 양의 변화량, 가속도 크기·변동·jerk, BVP 변동, 맥박수·맥박간격 변동·PRV RMSSD, 맥박 품질 플래그 |
| 맥박 품질 | 최소 20개 유효 간격, 전체 간격 중 80% 이상 0.33–1.5초. 실패한 맥박 특징은 NaN |
| 결측 | 훈련 참가자들의 중앙값으로만 대치. 품질 플래그와 대치 특징 목록 기록 |
| 모델 | 다수 클래스 Dummy, Logistic Regression(C=1), Random Forest(300 trees, depth=6, min leaf=5) |
| 불균형 | Logistic/RF class_weight=balanced; SMOTE 사용하지 않음 |
| 검증 | 15-fold LOSO. 14명 학습, 남은 1명 평가 |
| 주 지표 | 참가자별 Macro-F1의 평균; 참가자를 단위로 10,000회 부트스트랩한 95% 구간 |
| 보조 지표 | balanced accuracy, stress recall/precision, AUROC, Brier, 혼동행렬 |
| 설정 | seed=42, threshold=0.5, 이번 실험에서 튜닝 없음 |

참가자 ID·시간·조건 라벨은 모델 특징에서 제외한다. 테스트 참가자 개인 전체의 평균으로 정규화하지 않는다. 두 모델의 점수 차이는 기술적으로 보고하며, 같은 데이터를 반복 튜닝해 개선하지 않는다. 후속 튜닝 시 외부 LOSO 안에 훈련 참가자만 사용하는 내부 group CV를 둔다.

PRV는 손목 맥파의 간격 변동으로 ECG 기반 HRV와 동일하다고 단정하지 않는다. 60초 추정·단순 피크 검출은 교육용 근사다. 움직임에 의한 잡음, 품질 플래그·체온 등이 실험 상황의 대리 변수가 될 수 있으므로 특징별 기여를 점검한다. 5초 경계 제외는 휴리스틱이며 생리학적 회복을 보장하지 않는다.

원논문의 60초 창과 분할·특징·이동 간격이 다르므로 논문 재현 또는 논문 점수와 직접 비교라고 부르지 않는다.

## 설명 생성과 품질 검사

정확도 우승 모델을 사후 선택하지 않고 RF를 설명 대상으로 미리 고정한다. 모든 사례는 해당 참가자를 제외하고 학습한 RF의 out-of-fold 예측이다. 세 설명 모두 같은 fold 모델과 동일한 입력을 설명한다. 설명기의 배경·분위수·대치 기준은 훈련 데이터에서만 계산한다.

| 화면 | 표시 내용 | 품질 기록 |
|---|---|---|
| A: 설명 없음 | 예측 클래스와 모델 출력 점수, 원래 센서 특징 요약 | 공통 UI 기준 |
| B: SHAP | 절댓값 상위 3개 특징의 스트레스 출력 기여 방향·크기 | 전체 값 합 + 기준값 = 모델 출력인지 검사 |
| C: LIME | 상위 3개 조건과 국소 가중치 | 국소 R²와 근사 예측 오차; SHAP 수치와 같은 의미로 표시하지 않음 |
| D: Anchors | 최대 3개 조건으로 이루어진 규칙 | 추정 precision, coverage, 목표 precision 0.95 충족 여부 |

Alibi는 라이브러리이며 여기서는 AnchorTabular를 사용한다. Anchor precision은 규칙을 만족하도록 샘플링한 입력에서 모델 예측이 유지되는 비율이지 실제 정답률이 아니다. 규칙이 없거나 목표 precision 미달이면 그대로 '충분한 규칙을 찾지 못함'으로 표시한다. 설명은 인과 원인이나 행동 처방이 아니다. 센서값을 바꾸면 건강이 개선된다는 문구를 쓰지 않는다. 모델 출력은 보정된 개인별 스트레스 확률로 표현하지 않는다.

사례 선택은 RF의 TP/TN/FP/FN에서 각 최대 4개, seed=42, 가능한 서로 다른 참가자를 우선한다. 이는 오답 관찰을 위한 의도적 표집이므로 사례 집합의 정답률을 실제 모델 정답률로 발표하지 않는다. 16개보다 적으면 이를 기록하고 사용자 실험용 사례 수를 재설계한다. 사례를 설명 품질이 좋은 순서로 골라 바꾸지 않는다.

실행 중 설명기 검증 변경: 처음 시도한 interventional Tree SHAP에서 한 사례의 기여도 합이 RF 출력과 약 0.0030585 차이 나 검증에 실패했다. 최종 결과는 모든 사례를 tree_path_dependent, model_output=raw로 다시 계산했다. RF의 raw 출력은 클래스 확률이며 실제 predict_proba와의 합 일치를 1e-6 이내로 검사한다. 이 방식은 훈련 트리 경로의 표본 수를 배경으로 사용하며, 상관 특징 처리 가정이 interventional 방식과 다르다. 최초 시도의 설명은 최종 결과에서 제외했다. 모델·예측·사례 선택·LIME·Anchors 설정은 바꾸지 않았다. 이는 설명기 실행 검증을 위한 변경이며 사전등록된 실험이라고 주장하지 않는다.

## 2단계: HCI 사용자 실험 — 모집·수행 전

수업용 탐색 파일럿 16명(성인)을 목표로 한다. 이 수는 검정력 분석 결과가 아니다. 참가자 모집·동의·기관 또는 수업의 인간 대상 연구 절차는 실제 수업 진행자가 수행한다. 개인 건강 데이터는 새로 수집하지 않는다. 실제 참여 없이 설문 응답·통계적 유의성을 생성하지 않는다.

설계는 4조건 참가자 내 비교다. 참가자마다 서로 다른 16개 사례를 보고, 각 화면 유형에서 4개 사례를 본다. 동일 사례를 같은 참가자에게 반복 제시하지 않는다. 설명 방식은 Method A/B/C/D로 익명화한다.

순서 네 가지는 A-B-D-C, B-C-A-D, C-D-B-A, D-A-C-B(Williams 균형 순서)로 균등 배정한다. 사례는 TP/TN/FP/FN 하나씩으로 구성한 4개 묶음으로 나누고, 4개 순서 × 4개 사례 묶음 순환의 16개 조합에 1명씩 배정한다. 조건별로 각 오류 유형을 1개씩 보게 하고, 참가자 전체에서는 각 사례가 각 조건에 등장하게 한다. 실제 사례가 각 셀 4개 확보되었는지 확인 후 배정표를 사용한다. 블록 안의 사례 순서는 참가자 ID 기반 난수로 섞는다.

진행: 동의·목적 안내(3분) → ML 비전문가용 용어 안내와 연습 2건(5분) → 4개 블록(약 16분) → 사후 면담(5분). 연습은 평가 사례와 분리하고 같은 안내문을 사용한다. 실제 정답은 전체 판단 완료 후에만 공개해 학습 효과를 줄인다.

각 사례에서는 예측과 원래 특징 요약을 보여주고 다음 항목을 기록한다.

1. 모델 예측이 맞다고 판단하는가? 맞음/틀림/판단 불가.
2. 자신의 판단 확신도: 1–7점.
3. 이 상황에서 휴식 알림을 받겠는가? 예/아니오. 정답 행동으로 채점하지 않음.
4. 설명 또는 화면을 이해하기 쉬웠는가? 1–7점.
5. 제시 시작부터 판단 제출까지의 시간(ms).

각 블록 뒤 이해도 문항 3개를 제시한다. 기여도 또는 규칙을 정확히 읽는 문제 1개, 설명으로 실제 원인을 확정할 수 있는지 1개, 모델이 틀릴 수 있는지 1개다. 첫 문항은 화면 종류에 맞춰 문항 난이도를 파일럿으로 점검한다. 설명 없는 화면에는 화면에 실제로 있는 정보를 읽는 문제를 준다. 다른 질문을 쓰므로 총점 비교의 한계를 함께 밝힌다.

주 HCI 지표는 오답 사례에서의 잘못된 수용률(틀린 예측을 맞다고 판단한 비율)이다. 보조 지표는 정답 사례 수용률, 판단 불가 비율, 이해도, 판단 시간, 주관적 이해 용이성이다. 정답 라벨 자체도 실험 조건이므로 사용자 오류 판별 과제의 생태적 타당성이 제한됨을 밝힌다.

분석 단위는 사람이다. 사례 응답을 독립적인 참가자처럼 세지 않는다. 먼저 참가자별·조건별 평균을 산출하고, 주 지표에 대한 Friedman 검정 및 사전 지정한 A 대 B/C/D 비교에 paired Wilcoxon + Holm 보정을 적용한다. 파일럿에서는 효과 크기와 개인별 변화를 우선 보고한다. '판단 불가'는 기본 분석에서는 수용 아님으로 두고, 제외한 민감도 분석도 보고한다. 1개 조건의 오답 사례가 모두 누락되면 해당 참가자를 paired 분석에서 제외하고 수를 공개한다. 모델 종류와 설명 종류를 동시에 바꾸지 않는다.

결론은 WESAD 모델 분류 성능과 설명 UI에 대한 탐색 결과로 한정한다. 생산성 개선을 검증하려면 후속 무작위 실험에서 과제 수행량·오류율·완료 시간 등을 별도로 측정해야 한다.
